# Browser-first master implementation plan

## Risk slices

| Slice | Риск | Verification criterion |
|---|---|---|
| Semantic state expansion | Save migration и legacy data | Old save migrates safely; future save rejects; no UI owns simulation state. |
| Sensor/diagnostic layer | UI становится декоративным или непонятным | Selected layer changes canonical diagnostic wording; text/pattern/label stay equivalent. |
| Event and boundary cards | Случайность, нарушение resident agency | Each scenario has two foreshadows, two routes, voluntary adaptation and recoverable aftermath. |
| Policy/Governor | Automation скрывает стоимость | Preview equals commit; blocked rule reports reason and safe alternative. |
| Crisis/endings | Binary failure or farming | New baseline/Archive outcome, cooldown, anti-repeat gate and no resident score. |
| Presentation | Pitch overclaims product state | Every slide claim is registered as fact, authored next, or target. |

## Delivery sequence

1. Preserve master sources and publish the traceability/decision/claims records.
2. Add typed contracts and migration for sensors, scenarios, diagnostics, policies, reserve and recognition.
3. Add a browser tutorial plus two fair authored scenario chains.
4. Add semantic UI, local feedback export and accessibility fallbacks.
5. Test deterministic replay/save migration/preview parity and inspect responsive screenshots.
6. Build a maximum-12-slide publisher deck from verified scope, then pass protected GitHub CI and checkpoint.
